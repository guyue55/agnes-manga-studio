## 3. 升级路线（批次化，每批独立可验收）

> 每批的完成定义（DoD）：① 代码改动遵守现有模块边界（共享能力进 `consts.js`/`ui.js`/`api.js`，不散落在页面）；
> ② 新增行为都有回归钉（静态钉进 `tools/uitest.mjs`、行为钉进 `tools/browser-test.mjs`）；

避免新集合/新页面与旧缺陷叠加；批 4–7 是体验与效率的持续打磨。

## 5. 明确不借鉴（边界）

以下与我们的硬约束（**零 npm 依赖 / 本地优先 / vanilla JS ESM / 无构建 / 无用户系统 / SEA 单文件 exe**）
正面冲突，五份报告结论一致，**一律放弃**：

1. **技术栈整体**：React 19 + Vite 8 + TS + Tailwind + 40–48 个 npm 依赖 + shadcn/Radix（01 §8、02 §9、03 §10、05 §11-1）。
   能借的只有设计决策与交互模式，**不是代码**。
2. **PocketBase + Goja `pb_hooks` 后端**（03 §10、02 §9）：引入一个 Go 二进制 + JSVM + collection 抽象，
   直接摧毁 SEA 单文件分发；且 Goja 单线程陷阱（base64 逐字符解码锁死 → 502/524）在真 Node 里不存在。
3. **RunningHub 账号体系 / 计费代扣 / 沙箱域 SSO（699 行 `rhLogin.ts`）/ 作品广场社交**（03 §10、05 §11-4/5）：
   单机本地应用无跨域、无平台代扣、无多用户，整套无对象。

5. **`__DS_BURN__` 生成器 / Tailwind 构建期 class 提取 / Vite 插件源码注入**（01 §8）：
   破坏"改一行即生效"与"运行时可被 `ui-audit.mjs` 度量"。

   分别是"关页即断"、"8 幕同时打上游"、"超量静默丢数据"，都是反例。
