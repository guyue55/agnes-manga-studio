# 信息架构与流程主线 · 参考 Webeye-Video 的骨架（B5 批次依据）

> 症状（用户原话）："现在的 UI 和创作流程关联不强，整个 项目、功能、UI、能力都很分散"。
> 与 B1–B4 不是同一条轴：那三批治的是**设计语言、体验缺陷、组件质感**，这一批治的是
> **信息架构（IA）与流程主线** —— 东西都在，但用户不知道"现在在哪、下一步点哪儿"。
>
> 参考对象：`/Users/apple/Project/Git/Webeye-Video`（React19+Vite+Tailwind，**只借设计决策、不借代码**）。
> 证据说明：该项目的结论来自一次**只读源码研读**（带 `file:line` 引用），**未逐条复核**；
> 本项目（agnes）侧的结论全部是**自己读代码 + 真机验证**得出的。

## 一、参考项目的骨架（它凭什么"不分散"）

四层递进，每层只回答一个问题：

| 层 | 路由 | 回答的问题 |
| --- | --- | --- |
| 营销页 | `/` | 这东西是什么 |
| 项目列表 | `/workspace` `/projects` | 我有哪些项目 |
| 项目中枢 | `/project/:projectId` | 这个项目做到哪了 |
| 单集工作区 | `/project/:projectId/episode/:episodeId` | 这一集现在该干什么 |

三个可直接搬的设计决策：

1. **导航即进度条**。唯一的全局侧栏把 6 个入口写成"阶段 01–04 + 画布 + 提示词库"，而每个入口的
   **副标题是实时状态徽标**（`N 镜头` / `x/y 视频` / `就绪`）—— 用户不用点进去就知道哪一段还欠着。
2. **阶段不是路由，是持久化字段**。一集 = **一个**工作区，6 个阶段靠 `stage` 字段在同一屏换内容，
   刷新/重开回到你离开的那一段；项目上下文由**路由参数**持有（没有页面自带项目下拉）。
3. **每一行自带"下一步"**。镜头级 4 步 checklist（资产绑定/动作台词/关键帧/视频）+ 一个由同一状态机
   算出的 `下一步：…` CTA。**这不是向导（wizard），是"每行自带下一步"的看板** —— 用户永远不用想
   "我现在该去哪一页"。

## 二、我们的问题（自己读代码数出来的）

**项目上下文有 5 种口径**（本轮实测，`grep` 可复现）：

| 页面 | 原来的写法 |
| --- | --- |
| scripts | `params.project` 存在性检查 → 否则 `state.projects[0]` |
| novel | `params.project_id`（**别名**）→ `state.projects[0]` |
| storyboards / characters / images / videos | `params.project` → `state.projects[0]` |
| assets | `localStorage['agnes.assets.project']` → `''` |

后果不是"代码难看"，而是**用户可见的错**：在 A 页选好项目、切到 B 页又变回第一个项目；
同一个链接在不同页面上指向不同的项目；素材库那个页面切了项目连 URL 都不写（刷新就回去）。

**七段链只在工作台看得见**（补 16 做的 `renderPipeline`），其余 10 个页面都看不到"我卡在哪、
下一步点哪儿"—— 而那正是用户最需要它的地方（他已经在干活了，不在总览页）。

## 四、做的时候必须守住的纪律（本项目自己的教训）

- **同一份数据不许算两遍**：侧栏徽标、流程条、页头"下一步"三者都取自 `/api/story/pipeline`
  那一个端点；另算一套的代价不是多几十行，而是**两个数字会分叉**，而分叉没人看得出来。
- **侧栏会被 SSE 高频重渲染**：徽标数据必须**缓存 + 去抖**，否则每个事件一次请求（补 27 的同类）。
- **项目上下文只有一个入口**：任何页面自己解析项目都算回归，uitest 有结构棘轮钉住。
- **快照不是权威**：`state.projects` 是启动那一刻的列表，**不能**拿它判"项目存不存在"。
- **改的是"看不见的骨架"**：这类改动文本断言全绿也说明不了问题（补 35 的教训），
  每一条都要有**真机契约**（切页 / 换项目 / 深链 / 死链四个动作）。
