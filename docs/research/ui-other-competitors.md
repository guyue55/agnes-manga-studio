## 1. N2S：信息架构与关键页面流

### 1.1 IA 总览

- 单路由应用：`/`、`*` 全部重定向到 `/workbench`（N2S entry.js L22552），**一个页面就是全部产品**。
- 页面骨架（L22546）：`吸顶 Header(新建项目/历史项目/账户) → Hero 标题+步骤条 → 错误/登录横幅 → 当前步骤卡片（一次只渲染一步）→ "设定资产库"入口条 → 导出/保存条 → Footer`。
- 两个浮层：设定资产库 **居中模态**（JaComponent L22484）与历史项目 **右侧抽屉**（GaComponent L22432）。
- 步骤条 4 个具名步骤（`Qr`，L18639）：**① 粘贴原文 → ② 故事脉络 → ③ 角色设定 → ④ 分镜脚本**。
  "五步流水线"的第五步（设定资产）**不占步骤位**，而是第 4 步就绪后浮出的旁路面板；视频提示词（第 6 段能力）则内联在每镜卡片里。这个"4 主步 + 2 旁挂"的收束方式本身就是值得研究的 IA 决策（§2 详述）。

### 1.2 关键页面流（happy path）

```
粘贴/填充示例(47字内置小说 fa, L21014) ─▶ [开始拆解] 费用弹价确认 ─▶ ②脉络纯文本可编辑
  ─▶ [确认，提取角色设定] ─▶ ③角色卡网格(3-6张,appearance必填)+全局风格下拉首次露出
  ─▶ [确认，生成分镜脚本] ─▶ ④镜头卡列表(8-14张) 每卡两个折叠面板：
        画面提示词(计算态预览+AI润色→opt_prompt) / 视频多参数提示词(单镜或批量)
  ─▶ 底部出现 [设定资产库(N条)] ─▶ 模态内四类分组卡片 + TXT/JSON 导出
  ─▶ 全程底部导出条：项目名 + 成片脚本TXT / 分镜表CSV / 视频提示词MD / 保存云端
```

- 步骤跳转规则：**只能回到"曾经到达过"的步骤**（`maxVisited` 门，L21294 `goStep`、L18645 步骤条 disabled 态），前向只能靠"确认"按钮推进（L21299-21328），确认即触发下一步的**自动预生成**（角色列表为空时确认脉络会直接开始生成角色；同理确认角色生成第一版分镜）。
- 回退语义：回看不重算、不丢失——所有中间产物存在一个 `useFa()` 巨型 hook 的 React state 里（L21180-22163），改完再前进时才以"重新生成"显式重算（带确认弹窗）。
- 历史项目抽屉：右侧 `max-w-md slide-in-from-right`，卡片列出 封面位/名称/日期/镜头数/角色数，载入时按"最深有数据步"自动落位到对应步骤（L22015-22037：storyboard 有→4，characters→3，outline→2，否则 1）。

### 1.4 组件与微交互亮点

1. **步骤条胶囊**（L18645）：圆形序号+文案，激活=实心 primary、可达=白底 hover 描边、不可达=灰字 disabled；连接线 `h-px w-10`，已到达段用 `bg-primary/40` 点亮——三态一眼可读"我走到哪了、能退到哪"。
2. **费用透明门** `runWithCostConfirm`（L20965、Zr 组件 L18623）：每个会烧 token 的动作先弹小对话框，文案含"可能消耗 RH 币或钱包余额"+ **今天内不再提醒（仅对当前项目有效）** 复选框；主按钮 hover `scale-105`。付费焦虑被一个弹窗+一个勾选框消化。
3. **计算态提示词面板**（L22385）：镜头卡里"画面提示词（描述+全局风格+角色外貌）"是**实时拼装的只读预览**（max-h-40 滚动，whitespace-pre-wrap），配 [AI 优化提示词]（A5 润色→存入 `opt_prompt`，标注"可继续编辑，导出时一并写入"）。用户始终知道"机器最终会拿到什么词"。
4. **每卡双折叠 + 状态胶囊**：视频提示词折叠头常驻四态徽标 `未生成/排队中/生成中…/已生成/失败可重试`（L22388），失败态徽标本身就是重试按钮文案"重试生成本镜视频提示词"——错误状态不弹 toast，收进徽标。
5. **卡片内联编辑 + 幽灵按钮**：角色/镜头/资产卡全部就地可改（input/textarea 直接绑 patch 函数），无"编辑态/只读态"切换；卡片 hover 仅 `shadow-sm→md`。
6. **镜头重排**：上移/下移/删除三个 7×7 圆钮，删除后**全表重编号** `no=t+1`（L21393），移动后同样重编号（L21399）——编号永远是展示序，不承担身份。
7. **章节循环切换器**（L22244）：整本导入后 ↑↓ 按钮循环选章（到头回绕），章节列表行内"序号胶囊+标题截断+字数+·已填入"，选中行 `bg-primary/10 text-primary`。
8. **空态引导**：分镜空→"可手动添加镜头，或回到上一步重新生成"；资产空→大虚线卡+主按钮"开始提取设定资产"；每个空态都给出**下一步动作**而不是干巴巴一句"暂无数据"。

## 2. N2S 五步流水线逐步拆解

> "五步"按提示词块计（A1-A5 核心 + A0 前置 + 3 个改写器旁挂，PROMPTS.md 九段逐字已存）。
> UI 侧映射为：A0 藏进步骤①的数据准备；A1/A2/A3 对应步骤②③④；A4（设定资产）旁挂为模态；
> A5（视频词）内联进步骤④镜头卡。全部经统一 `M(system,user)` → `POST /api/llm/{model}/chat`
> （model 常量 `gpt-5.5`，page 埋点 `workbench`，max_tokens 8192，L20971-20972、L21210-21232）。
> 每步 user 消息都是"**上游全部产物 + 小说原文回注**"，这是它一致性的根基。

### 步骤 ⓪/A0 · 原文进入（正则分章 + LLM 抽样校对）
- **用户操作**：粘贴到 min-h-72 大 textarea（字数实时统计，<100 字软提示"建议至少 100 字"，L22176）；或"选择文件导入"上传 .txt/.md——**编码三重兜底**：10MB 上限 → UTF-8 fatal decode → 失败退 GBK → 再失败按 UTF-8 宽容解码（L22182-22216），文件名自动填项目名。
- **模型契约**：A0 校对员（ja，L21167）只回 `[{title,excerpt}]` JSON 数组；**主链路其实是纯正则**（`Oa`：第X章/回/卷…+中文数字全表+Chapter N 罗马数字，剥离 Markdown `#`，>36 字不算标题，相邻<2 行去重，空段过滤，L21129-21165）。仅当用户点"AI 智能分章"才按 9000 字×最多 10 片抽样送 LLM 找漏（L21168-21174、L21765-21827），结果用 `indexOf` 定位回原文切段，**要求 ≥2 章才采纳**，否则保留正则结果并提示。
- **UI 呈现**：步骤①同时挂两张卡：粘贴卡 + "导入整本小说"卡（章列表可搜索、循环切换、点章回填粘贴框）。
- **失败/回退**：识别不出章节时横幅引导点 AI 分章（按钮此时自动升格为 primary 实心，L22244）；LLM 分章失败保留正则结果可继续。

### 步骤 ①→②/A1 · 故事脉络
- **用户操作**：点"开始拆解"（primary 大胶囊，禁用态=空文本/loading）。
- **模型输出契约**：**唯一非 JSON 步**——纯文本三段：【主线梗概】≤80字 /【场景分段】3-8 行「场景N：标题——关键事件」/【情绪节奏】箭头链+破折号注因（ma，L21028）。选纯文本是有意的：这一步产物给人读、被用户手改，无需结构。
- **UI 呈现**：结果灌进可编辑 textarea（min-h-64），副标题写明"可直接在下方修改，满意后再进入下一步"；loading 用 4 条 `animate-pulse` 骨架 + "通常需要半分钟左右…"的时间预期文案。
- **失败/回退**：错误进全局红色横幅（可 ✕ 关闭）+ 按钮原地变"重新生成"；无自动重试。产物 `outline` 是字符串 state，[确认，提取角色设定] 才推进并触发 A2。

### 步骤 ②→③/A2 · 角色设定
- **用户操作**：确认脉络即自动开跑（也可在步骤③内"重新生成"）。产物渲染为 3-6 张角色卡网格（sm:2/xl:3 列），每张卡就地编辑 姓名/身份/**外貌 textarea**/性格/出场场景，虚线幽灵卡"+ 添加角色"，卡尾"删除"。
- **模型契约**：JSON 数组 `name/role(≤10字)/appearance(≤60字，必须含发型服装体态显著特征，注明"供 AI 绘图保持角色一致性")/personality(3-5)/scenes`（ha，L21032）。解析后逐字段 `String(e.x ?? 兜底)`，缺 name 给"未命名角色"（L21253-21260）。
- **一致性设计（本报告重点）**：`appearance` 是**贯穿全链的一致性载体**——① 注入 A3 分镜师 user 消息（"姓名（身份，外貌）"分号串）让镜头知道谁长什么样；② 生成每镜画面提示词时按 `character_names` 反查角色，拼"出镜角色外貌一致性：name——appearance…"（`Ue`，L21359-21363）；③ 视频提示词的上下文里再给全量"全片主要角色"名单（`Ye`，L21478-21492）。角色卡副标题直接把机制说破："外貌描述会拼入对应镜头的画面提示词，保持角色一致性"（L22325）——**把内部一致性策略当 UI 文案教给用户**，用户因此懂得认真改外貌栏。
- **失败/回退**：JSON 解析统一走兜底器 `Ea`：剥 ```json 围栏→按期望类型找首尾括号截取 parse→失败抛"AI 返回内容解析失败，请重试"（L21116-21127）；一个函数走天下。

### 步骤 ③→④/A3 · 分镜脚本
- **用户操作**：确认角色即自动开跑；镜头卡列表逐镜就地编辑（景别 select、时长/运镜小 input、画面描述/台词 textarea、↑↓✕）。
- **模型契约**：8-14 镜 JSON：`no/shot_size(远景|全景|中景|近景|特写 枚举 da)/description(40-80字，人物动作+环境+光线，有镜头感)/dialogue(一句)/duration(如 3s)/camera(推拉摇移跟固定)/characters(字符串数组)`（ga，L21034）。解析兜底：缺 shot_size→中景、duration→3s、camera→固定（L21281-21285）。
- **UI 呈现**：loading 是 3 组"镜头卡轮廓"的骨架屏 + "通常需要一分钟左右…"；顶部计数条"已生成 X / N 镜"；旁挂工具 [添加镜头] 与批量 [生成分镜视频提示词]。
- **改写旁路**：每镜 [重新生成本镜文案] 走 A4 改写器（_a，L21036：保持编号与出场角色）；[AI 优化提示词] 走 A5 润色器（va，L21037：保留镜头编号/景别/角色外貌要点/全局风格）——**改写器提示词的共同句点是"保留上游锚点"**。
- **失败/回退**：同全局横幅；分镜空→引导"回上一步重新生成或手动添加"；删除/移动即时重编号，无确认无撤销（工具型容忍度）。

### 旁挂/A4 · 设定资产库（四类资产）
- **用户操作**：分镜就绪后底部浮出 [设定资产库（N 条）] 主按钮；打开即自动提取（空时）或点"重新提取资产"。模态内按 人物/服装/物品道具/场景 四区，每区计数徽标 + "+新增X"；卡内 名称/外观描述/文生图提示词 就地编辑 + [重新生成提示词]（A7 重写器 ba，L21041）+ 删除。
- **模型契约**：`category(四类之一)/name(≤12字)/description(≤60字)/prompt(120-200字)`，数量配额 人物3-6/服装2-6/道具2-6/场景3-6，且"全部从剧情中真实出现的内容提取"（ya，L21038）。解析后 category 不在枚举内→归"场景"，prompt 空的条目直接丢弃，全军覆没才报错（L21593-21606）。
- **关键设计**：生成的资产 prompt **明令禁含全局画风词**（"画风由外部统一注入"）；卡上提示词条目挂 `已注入全局风格` 小徽标（L22480）提醒用户：存储的 prompt 与最终用的 prompt 不是一回事。
- **素材引用真实形态**：两站都**没有**文本框里 `@角色名` 那种 mention 语法（N2S 业务区实测无 `@` 解析）。所谓"素材引用"是两套机制：① N2S 靠 `Ye()` 把"已提取设定资产摘要 + 全片角色外貌"以纯文本回注进视频词上下文（见下文 A5）；② MJ 靠"引用卡"卡片多选把档案文本 + 封面/图集注入，且在场景卡名后以 `@{region_name}` 展示其父级地块（如 `【场景·名字 @某地块】`，MJ entry.js L45434），是**跨图集层级标注**而非用户手输语法。抄的时候别去实现 `@` 输入解析，要抄的是"回注 / 勾选"这两条真实链路。
- **失败/回退**：未出分镜先点提取→拦截"请先生成分镜脚本，再提取设定资产"（顺序防呆，L21616）。

### 内联/A5 · 多参数视频提示词
- **用户操作**：镜头卡折叠面板单镜生成/重试，或列表顶一键批量。
- **模型契约**：JSON 对象七字段 `first_frame≤50字/subject_action≤40字/camera_move≤20字/duration/light_mood≤30字/style≤20字/audio≤40字`（xa，L21042），user 消息回注 该镜+全局风格+出镜角色+全片角色+**已提取设定资产摘要**+故事脉络（`Ye`，L21478）——资产库与视频词之间的隐性数据边。
- **UI 呈现的巧思：七参数人机双向格式**。存储态不是 JSON 而是 `标签：值` 多行文本（`Sa` 字段↔中文标签字典 + `Ca` 正格式化，L21045-21084；`wa` 反向解析，L21085+）。用户手改文本后，导出时 `wa` 仍能结构化回收为 MD 列表——**牺牲存储形态换编辑自由**。
- **批量调度**：`Promise.all` 并发全表（L21503-21535），每镜状态机 `queued→running→(成功清除|failed)` 点亮卡头徽标；再次点击只补做缺的（filter 无 video_prompt 者，L21544），已完成的单独重试。
- **失败/回退**：单镜失败标 `失败可重试` 不连坐；空结果抛"视频提示词生成结果为空，请重试"。

## 3. N2S「全局风格注入」体系

- **组织**：两个常量——`la` 12 款风格名数组（电影写实/国风动漫/赛博霓虹/水彩绘本/美漫厚涂/日漫清新/水墨武侠/像素复古/油画古典/3D 皮克斯/暗黑哥特/治愈小清新，L20979-20992）+ `ua` 名称→注入文案字典（每款≈一句话、含流派词+光影+质感关键词，L20993-21006）。默认 `la[0]`。
- **注入点**：唯一函数 `N()`（L21356-21358）拼 `全局画面风格：{名称}，{ua文案}，细节丰富`，出现在三处：① 每镜计算态画面提示词 `Ue` 尾部；② 设定资产最终词 `et()`=`prompt + 。 + N()`（L21578）；③ 视频提示词 user 上下文。风格下拉在步骤③角色卡头部与步骤④镜头区各出现一次（常驻 `bg-secondary` 条），**切换即时全量重算提示词预览**（因为提示词是计算态、非落库）。
- **解耦纪律**：三条生成链的 system prompt 里反复申明"禁止包含任何全局画风/风格流派词，画风由外部统一注入"（A6/A7）；A5 润色器反向要求"保留全局画面风格要求"。即：**模型负责"画什么"，字典负责"怎么画"**。
- **与我们做法对比**：
  | | N2S | 我们（agnes-studio 本地版） |
  |---|---|---|
  | 画风存哪 | 12 款内置字典 + 项目级单选 `globalStyle` | `project.art_style` **自由文本**（projects.js L134），模板里 `画风:{{画风}}`（seed.js L103） |
  | 何时进提示词 | **使用时拼接**（派生），模型产物永不含风格词 | 生成图片提示词时让 LLM 把画风**写进产物**（seed 模板要求如此） |
  | 换画风成本 | 改一次下拉，所有镜头/资产提示词自动换血，零 token | 逐条重新生成，或手动批量替换 |
  | 风险 | 字典文案质量=天花板，用户想选第 13 款没有 | 自由文本无标准，同项目多次生成画风漂移 |
  | 借鉴 | 两者可以合：**自由文本风格 + 12 预设做"配方"**，且把注入时机后移到"使用点" | — |
- 结论：这是两竞品中最有移植价值的一件事——**画风词与内容词分层、内容层保持风格中立**，能直接降低我们分镜图/视频阶段的重生成浪费。

### 5.3 组件与微交互亮点（MJ）

1. **保存状态胶囊**：idle 不渲染 / 保存中(spinner) / 已保存(✓ primary/10) / 保存失败(✕ destructive/10)（`P1Component` L33548）；设定页底部常驻"设定会自动保存 · 已填 N/8"完成度计数（L39590，`hx()` 逐字段数）。

3. **数据驱动参数面板**：`BComponent` 按模型目录的 `scalar_params/media_params` 元数据自动渲染开关/下拉/数字框/上传位，枚举里 `empty|-1` 统一显示"自动 / 不指定"，必填加 `*` 标（L37313）；无参数时明说"当前模型无可调参数，按默认配置生成即可"。目录来自 `GET /api/aigc/models`——**面板零硬编码**。
4. **弹价门 + 用量回执**：每次生成前 `runWithCostConfirm` 弹价（18 处调用点，含"今天内不再提醒"），生成后卡底回显 `最近任务 {id} · 消耗 {money}`（L38xxx Ex1 尾）。价格试算走 `POST /api/aigc/price-preview`，body 与真实提交同构。

6. **防误触两连**：删除镜头按钮第一次点击变成"确认删除？"（同位文案切换+变色），第二次才删（L41686 一带）；覆盖已有生成结果（重绘/重写）先二次确认（MANIFEST 记"已有提示词，再点会覆盖"）。

8. **上传版本协商**：`/api/aigc/media/upload` 404 → 永久回退 `/api/aigc/upload` 并缓存判定（`qh` 标志，L31273）；LLM 网关同款 `O_` 协商（`/api/llm/{task}` ↔ `/api/llm/{model}/{task}`）。对"平台端点不确定"的鲁棒模式。

### 5.4 MJ 提示词工程与 N2S 的分工关系

- **MJ 六段 LLM 提示词**（P-01…P-06，逐字见其 PROMPTS.md/inventory）：全部分集剧情/单集重写/角色提取/场景提取/剧情拆分镜★/**视觉素材反推分镜（多模态）**。共同范式：字段级字数与枚举约束 + `{"key":[…]}` 对象壳（非裸数组）+ "只输出一个 JSON 对象，不要任何解释" + 前端 4 个解析兜底函数。P-05 把 **settings.art_style 以 `[画风设定：…]` 行注入 user 消息**、并要求 scene_name/character_names 优先复用清单名，后端再 `qS/JS` 名字→id 匹配落库——比 N2S 多了"名字对齐到实体"的闭环。
- **MJ 生图/生视频模板**（T-01…T-09）：立绘/五槽图集/世界观四图集/素材设定图/分镜画面/短片合成/TTS——全部**本地字符串拼装**（模板+插值+固定护栏句，如"不出现人物，画风统一，适合漫剧设定图"），不经过 LLM，零 token；用户草稿可整体替代模板。T-07 合成词 = `【设定约束】+【引用卡】+【导演台】+【镜头描述】` 四段，导演台五枚举（景别6/运镜9/节奏4/情绪8）与 `PC` 约束（画风/比例/对白基调/旁白基调/时代/地点/氛围，逐字段非空才写入）是**参数面板直出提示词**的范本。
- **分工关系**：
  - 路径：N2S 吃"存量小说"做改编拆料；MJ 吃"原创点子"从剧情长起。同一作者把一条链拆成两站：N2S=上游拆料（文本→结构→提示词），MJ=下游制片（结构→图→声→片）。
  - 能力镜像差异：N2S 有"正则+LLM 抽样校对"分章（MJ 无此需求）；MJ 有 AIGC 提交/轮询/弹价/上传协商全家桶（N2S 纯文本工具，产出物=词）。N2S 一致性=appearance 三回注；MJ 一致性=**设定版块单一事实源**（P-05/T-06/T-07 三处读同一 `settings.art_style`，L41877 附近注释确认同源）+ 图生图参考图（主形象封面当底图出三视图/细节/技能/装备）。
  - 风格注入哲学相反：N2S 用**枚举字典在使用点拼接**；MJ 用**自由文本在生成点注入** + 参考图在像素层锁风格。MJ 更接近我们现状，N2S 更接近我们应去的方向。

## 7. 不值得学清单

1. **前端明文持提示词**：两家都把创作大脑写在 bundle 里（N2S 9 段、MJ 6+8 组模板），上线即裸奔；我们服务端 `lib/` 路由模板的既有架构恰好是对的，别倒着走回去。
2. **无撤销的状态模型**：删除/重排/重生成都即时且不可回退，靠"用户小心"兜底；我们本地 JSON 库做版本化/回收站反而更便宜。
3. **`Promise.all` 无限并发批量**（N2S Ze，14 镜=14 并发 LLM 请求）：对代理网关不友好，失败风暴时只有逐镜徽标；我们的 jobs+poller 队列模型本就更稳，别学它的"快"。
4. **单 hook 巨型状态**（useFa 约 1000 行、40+ state）与 **4 个解析器/一个 Ea 走天下**：阅读树里它俩是事故现场，不构成 UI 结论但提醒我们保持 lib/ 拆分纪律。
5. **`no` 字段当展示序号用**：移动即重排全表、导入即信任 AI 的 no——我们按 id 存储、展示序另算即可，别学字段语义混用。
6. **蹭品牌字体与云依赖**：`Airbnb Cereal VF` 字体栈（无 @font-face，纯蹭名）与 `/api/comic_projects` 平台云存强绑 RunningHub 账号——与我们零依赖本地优先相反。
7. **`--sidebar-*` 等未定义 CSS 变量**（MJ）：抄它配色时注意补全，别照搬 token 名。
8. **标题即生成 prompt 的裸发布**（N2S `<title>` 忘记改，MANIFEST 记为"反向工程天崩开局"）：提醒我们发布前过一遍 `<title>`/埋点/analytics 外链这类门面项。
